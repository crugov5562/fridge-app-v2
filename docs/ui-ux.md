UI/UX правила
You are an expert in mobile UI and UX design for FridgeAI — приложение учёта продуктов с ИИ. Стек: React Native + Expo + NativeWind. Эстетика: минимализм Apple — clarity, restraint, content-first hierarchy. Читай этот файл перед любой UI-задачей.
Core Philosophy

Less, but better. Каждый видимый элемент должен оправдывать своё присутствие — если не оправдывает, удали.
Content is the interface. Хром (рамки, тени, декорации) отступает на задний план; то, за чем пришёл пользователь, на переднем.
Clarity over cleverness. Пользователь не должен догадываться, что делает кнопка или где он находится.
Consistency builds trust. Одно и то же действие выглядит и ведёт себя одинаково везде.
Motion has meaning. Анимация коммуницирует состояние и иерархию, а не украшает.

Visual Design

Чёткая визуальная иерархия через размер, вес, расстояние — не через рамки и фоны.
Ограниченная палитра: одна нейтральная шкала, один акцентный цвет для основных действий, семантические цвета только для статусов (success, warning, error).
Все цвета, отступы, радиусы и типографика — токены в tailwind.config.js. Никогда не хардкодить значения в компонентах.
Семантические имена токенов (bg-background, text-primary, border-separator), а не сырые (bg-white). Они автоматически переключаются с dark:.
Типографика: один современный нейтральный sans-serif (Inter, SF Pro, Geist через expo-font). Максимум 3-4 типографических уровня на экран.
Контраст по WCAG 2.1 AA минимум (4.5:1 для текста, 3:1 для крупного и UI). Тестировать в светлой и тёмной теме.
Тонкие разделители (1px, низкий контраст) предпочтительнее заполненных карточек.
Мягкие поверхности вместо тяжёлых теней. Если нужна elevation — субтильный сдвиг фонового тинта раньше тени.
Одна шкала радиусов (rounded-xl, rounded-2xl). Без смешивания крайностей без причины.
Иконки: одна библиотека (lucide-react-native), один вес, размер совпадает с соседним текстом.

Interaction Design

Используй платформенные паттерны навигации. Стек, табы, модалки — то, что пользователи уже знают.
Одно primary action на экран. Вторичные — ghost или text-only кнопки.
CTA однозначные: глагол на первом месте («Добавить продукт», «Отправить», «Продолжить»). Никогда «ОК», «Submit».
Touch targets минимум 44×44pt (Apple HIG). Между ними щедрый зазор.
Мгновенный отклик на каждое касание в пределах 100ms — opacity, цвет, haptic. expo-haptics для primary actions, подтверждений и ошибок.
Используй active: варианты Tailwind для нажатий. Никогда не оставляй тап без видимого ответа.
Анимации: ease-out для входа, ease-in для выхода, springs для жестов. Длительность 200–350ms для UI, 150ms для микро-взаимодействий.
react-native-reanimated (worklets, UI thread) и moti (декларативные входы). Legacy Animated API — нет.
Layout transitions (LinearTransition) для перестройки списков и смены высоты — пространственная непрерывность.
Уважай prefers-reduced-motion.

Accessibility

Каждый интерактивный элемент: accessibilityLabel, accessibilityRole, accessibilityHint где действие неочевидно.
Тестируй с VoiceOver (iOS) и TalkBack (Android) на каждом экране.
Не передавай смысл только цветом. Сочетай с иконкой, текстом или формой.
Поддерживай dynamic type / масштабирование шрифтов. Используй относительные размеры Tailwind, не клампь текст в фиксированную высоту.
Логичный порядок фокуса при навигации с внешней клавиатуры или switch control.
Альтернативный текст для изображений через accessibilityLabel на Image/expo-image.

Performance and Responsiveness

Изображения: expo-image для кэша и современных форматов. Явные width/height чтобы не было layout shift.
Lazy-load тяжёлых экранов через автоматический code splitting Expo Router.
@shopify/flash-list вместо FlatList для любого растущего списка. Всегда keyExtractor, estimatedItemSize, removeClippedSubviews.
renderItem и обработчики событий вне рендера или через useCallback — никаких inline стрелок в элементах списка.
Стримить ответы LLM токен за токеном. Никогда не блокировать UI спиннером, пока модель генерирует.
Optimistic UI там, где результат предсказуем (отправка сообщения, тогл избранного).
Skeleton-экраны, повторяющие финальный layout, а не общие спиннеры — кроме коротких ждаций (<1s).

Responsive and Adaptive Layout

Дизайн под самое маленькое устройство (iPhone SE), масштабирование вверх до планшетов.
Используй Tailwind spacing scale (p-4, gap-3) — никаких хардкоженых пикселей вне конфига.
Flexbox для всего layout. Абсолютное позиционирование только для оверлеев.
Уважай safe areas: SafeAreaView из react-native-safe-area-context или useSafeAreaInsets.
Тестируй portrait и landscape; маленький телефон, большой телефон, планшет.
Корректируй типографику и отступы на брейкпоинтах когда нужно — не масштабируй всё пропорционально.

User Feedback

Loading: skeleton-ы для первичной загрузки, inline спиннеры только для коротких ождиданий, прогресс-бары для определённых операций.
Success: тихо когда ожидаемо (сообщение отправлено), явно только когда действие значимо (документ загружен, аккаунт создан). Краткий toast или inline confirmation.
Errors: что произошло, почему, что делать. Никогда не показывать сырые коды или stack traces. Дай retry.
Empty states — это дизайн, а не вторичное: короткий заголовок, одна строка объяснения, одно primary действие.
Деструктивные действия требуют подтверждения. Где возможно — undo.
Haptic feedback для primary actions, подтверждений и ошибок — экономно, чтобы оставался смысл.

Information Architecture

Группируй по задачам пользователя, не по структуре данных. Что вместе делается — вместе.
Чёткие ярлыки на простом языке. Без жаргона, без аббревиатур.
Expo Router segments ((tabs), (auth), (modal)) зеркалят навигационную иерархию в коде.
Поиск — first-class citizen, если у приложения есть содержательный корпус.
Progressive disclosure: главное вперёд, детали по запросу.

Mobile-First Touch Patterns

Primary actions в зоне большого пальца — нижняя половина экрана, особенно на больших телефонах.
Bottom sheets (@gorhom/bottom-sheet) для контекстных действий, фильтров и пикеров вместо полноэкранных модалок где можно.
Стандартные жесты работают: swipe-to-go-back, pull-to-refresh, swipe-to-delete на элементах списка.
Long-press для вторичных действий — но всегда с видимой альтернативой (long-press недискаверабельный).
Зазор между touch targets минимум 8pt чтобы не было промахов.

Forms and Input

Нативные типы клавиатуры (keyboardType="email-address", "numeric").
Inline валидация: на blur, не на каждый keystroke. Success тонко, errors чётко.
Сообщение об ошибке под полем, в семантическом цвете, с иконкой для неколорового сигнала.
Auto-focus первого поля при открытии формы. Auto-advance через returnKeyType и onSubmitEditing.
react-hook-form + zod схемы.
Избегай required полей где можно. Если обязательно — отметь чётко.
Affordances ввода (clear-кнопка, password reveal, счётчик) только когда они полезны.

Consistency and Design System

Маленькая, мнение-обоснованная библиотека компонентов: Button, Input, Card, Screen, Header, EmptyState, Skeleton, Toast. Используй их вместо разовых стилей.
class-variance-authority (cva) для вариантов компонентов. cn() (clsx + tailwind-merge) для условных классов.
Единая терминология. «Продукт» или «товар» — выбери одно. «Войти» или «Авторизоваться» — одно.
Повторяющиеся элементы (back button, primary action, заголовок) на одной и той же позиции на каждом экране.
Dark mode не опциональна. Каждый компонент поддерживает её через dark: варианты.

AI и RAG Interface Patterns
Это критично для FridgeAI — большая часть ценности приходит через ИИ-фичи.
Распознавание чека и фото

Покажи живой preview камеры с подсказкой: «Наведите рамку на чек», «Уместите все продукты в кадр».
После снимка — немедленный visual feedback (затемнение и спиннер), что обработка началась.
Прогресс с конкретными статусами: «Распознаём текст», «Классифицируем продукты», «Проверяем сроки годности» — не один общий спиннер.
Результат не финальный: всегда экран подтверждения с возможностью отредактировать каждую позицию (название, количество, дату, категорию).
Если ИИ не уверен (низкая confidence) — пометить позицию визуально, попросить юзера проверить.
Если распознавание провалилось — конкретная ошибка («Чек слишком размыт», «Не нашли товаров на фото») и кнопка retry или ручной ввод.

Подбор рецептов через RAG

Стримить генерацию объяснения: «Я выбрал этот рецепт, потому что у тебя есть курица, рис и морковь, и он не содержит арахис, на который у тебя аллергия...» — токен за токеном, не блокируй спиннером.
Покажи thinking indicator (тонкий, не огромный спиннер) пока модель обрабатывает запрос до прихода токенов.
Показывай покрытие ингредиентов наглядно: галочка зелёная (есть), серая (нет), полупрозрачная (есть, но кончается).
При свободном запросе — поле ввода с подсказками-примерами: «быстрый ужин из курицы», «что-то острое и сытное», «низкокалорийный завтрак».
Делай retrieval инспектируемым: collapsible секция «На основе чего я подобрал» — список найденных рецептов с similarity score (можно даже без числа, просто визуально).
Кнопка «Перегенерировать» или «Другие варианты» — модели ошибаются, юзеру нужен escape.
Различай AI-сгенерированный текст и user content визуально (фон, отступ, иконка sparkle/wand).
Обрабатывай AI-фейлы явно: rate limit, timeout, content filter, network — у каждого свой ясный, actionable message.
Никогда не показывать API-ключи, сырые промпты или внутренние ID.

Голосовой ввод

Большая, очевидная кнопка записи в центре. Меняет состояние во время записи (пульсация, цвет).
Live waveform или хотя бы анимация во время записи — feedback, что микрофон слышит.
Транскрипт показывать сразу после остановки. Юзер должен видеть что услышали, прежде чем отправить.
Возможность переписать или отредактировать транскрипт перед отправкой.
Тайм-лимит (30-60 сек), визуальный индикатор оставшегося времени.

Уведомления о сроках

Понятное, человеческое сообщение: «Молоко истекает завтра. Можно приготовить блинчики или панкейки.» — не «Item ID 42 expires in 1 day».
Группируй несколько истекающих в один daily digest утром, не спамь.
Tap по уведомлению — сразу к продукту в инвентаре, не на главный экран.

Инвентарь

Цветовая индикация срока: зелёный (>5 дней), жёлтый (1-5), красный (≤1). Дублируй цвет иконкой/текстом для accessibility.
Карта холодильника как визуальная альтернатива списку: продукты в зонах, как они должны лежать. Это уникальная фича — выделяй её.
Свайп влево по позиции для быстрых действий: «Использовал», «Выбросил», «Уменьшить».
Empty state «Холодильник пуст» с двумя primary действиями: «Сканировать чек» и «Добавить вручную».

Testing and Iteration

Тестируй на реальных устройствах, не на симуляторах. Touch feel, шрифты и производительность отличаются.
VoiceOver и TalkBack — до выкатки нового экрана, не после.
Maestro для end-to-end критических потоков (вход, сканирование, рецепт).
Лёгкие in-app prompts для сбора feedback после ключевых действий — но никогда не прерывай поток.

Что не делать

Хардкоженых цветов, размеров шрифта или отступов вне tailwind.config.js.
Больше одной primary кнопки на экран.
Декоративных анимаций, градиентов или теней без цели.
Смешивать UI-библиотеки (NativeBase + Reusables + Tamagui в одном приложении).
Пропускать empty, loading и error states — они не опциональны.
Generic спиннеров где skeleton передал бы больше.
Long-press как единственный способ доступа к действию.
Стен опций. Если на экране больше одной первичной задачи — раздели.
Сырых кодов ошибок, stack traces или технического жаргона для пользователя.
Показывать «AI is thinking» дольше 2 секунд без какого-либо прогресса или возможности отмены.

Держись Apple Human Interface Guidelines, Material Design (где Android-специфика) и современных мобильных паттернов. Когда сомневаешься — посмотри на Things, Linear Mobile, Bear, Notion, Raycast.
